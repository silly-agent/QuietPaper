# AI 数据库操作演示设计

## 目标

用一套可重复运行、不会接触真实业务数据的环境，展示 Quiet Paper 从建立数据库连接到自然语言查询结果的完整路径。演示应让读者一眼看出连接类型、用户问题、AI 生成的 SQL 和表格结果，同时避免在截图或仓库中出现真实密码、API Key 与个人数据。

## 方案

仓库提供 `docker-compose.demo.yml` 和 PostgreSQL 初始化脚本。容器只绑定本机 `127.0.0.1:55432`，使用明确标注为演示用途的账号密码。初始化脚本创建 `customers` 与 `orders` 两张表，填充虚构客户、订单金额、渠道和状态。应用侧使用 `--in-memory-preview` 启动独立实例，连接文件与聊天记录只存在内存数据库中，不写入用户的 Quiet Paper 工作区。

演示问题为“统计每个客户的订单数和有效消费金额，排除退款，按消费额从高到低取前 5 名”。应用先读取 PostgreSQL 结构，把脱敏后的结构和问题交给数据库助手；助手生成单条只读 SQL，本地执行器检查命令后在 Docker 数据库执行，并将 SQL、简短说明和结果表格保存在同一条会话中。

## 验收

先用 `pg_isready` 检查容器健康，再直接执行等价 SQL 验证预期结果。界面截图必须来自内存预览实例，截图前检查可访问性文本，确认没有真实笔记、API Key 或非演示凭据。提交前运行项目测试、敏感信息扫描和远端文件树检查。容器保留运行，方便继续测试；需要清理时可执行 `docker compose -f docker-compose.demo.yml down`。
