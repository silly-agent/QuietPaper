# 编辑区查找设计

## 目标

Quiet Paper 的当前笔记在编辑模式和预览模式下都支持 `Command-F` 查找。查找栏打开后自动获得焦点，Enter 向后跳转，Shift-Enter 向前跳转；越过最后或第一处匹配时循环到另一端。

## 交互

- 查找栏位于编辑器标题区与正文之间，不随正文滚动。
- 输入关键词后立即搜索，使用不区分大小写和宽度的本地字符串匹配。
- 查找栏显示“当前序号 / 总数”；没有结果时显示“无结果”。
- Enter 选择下一处，Shift-Enter 选择上一处，Escape 关闭查找栏。
- 编辑和预览切换时保留关键词，并针对当前模式重新计算结果。
- 切换笔记时关闭查找栏并清空关键词，避免继承上一篇笔记的上下文。

## 架构

`NoteEditorView` 持有统一的查找会话状态并展示查找栏。一个纯值类型负责查询、匹配范围与循环索引，使导航行为可以脱离 UI 测试。

编辑模式直接在 `PastingTextView` 的 Markdown 原文中查找，通过 `NSRange` 更新选区并滚动到可见区域。文本视图拦截 `Command-F`，把打开查找栏的意图回传给 SwiftUI。

预览模式针对渲染后的可见文本建立按块排列的搜索单元。每个标题、段落、列表项、引用、代码块和表格单元格都可提供匹配项；SwiftUI 为全部匹配添加背景色，为当前匹配添加更醒目的颜色，并使用 `ScrollViewReader` 将当前匹配所在单元滚动到可见区域。图片本身不参与搜索，图片说明文字参与搜索。

## 验证

- 单元测试覆盖首次匹配、向前/向后循环、无结果、大小写与中文查询。
- 编辑器 AppKit 检查覆盖 `Command-F` 回调、选区更新和滚动导航。
- 预览数据测试覆盖 Markdown 标记被移除后仍能匹配可见文本，并验证列表、代码和表格内容的顺序。
- 最后运行 `./scripts/run-tests.sh`；测试继续使用内存数据库，不接触正式数据库。
