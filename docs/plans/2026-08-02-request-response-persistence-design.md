# 请求响应持久化与交互细节设计

## 产品行为

请求配置继续使用 600ms 合并自动保存。每次发送只更新会话响应；用户点击“保存响应”后，当前响应才会写入请求文件。一个请求最多保存一份响应，再次保存覆盖旧值。重新打开请求时自动展示已保存响应，并显示“已保存”标识和保存时间；用户可移除已保存响应。保存内容包括最终 URL、状态码、Headers、格式化后的 Body、耗时、字节数和保存时间，响应正文不加入全文搜索。

Method 从其他类型切换到 POST 时，如果请求中不存在任何大小写形式的 `Content-Type`，自动新增一条启用的 `Content-Type: application/json`。如果用户已经配置同名 Header，无论启用或停用，都不重复添加或覆盖。切换离开 POST 时保留该 Header，尊重用户随后做出的修改。

响应数据进入界面前统一尝试解析 JSON。对象、数组与合法 JSON 标量均使用稳定缩进和键排序格式化；无法解析时按 UTF-8 容错文本显示。界面展示、复制和保存使用同一份格式化结果，避免三处内容不一致。

## 数据与兼容

`HTTPRequestDraft` 升级为版本 2，并增加可选 `savedResponse`。响应使用独立的 Codable 值类型，Header 不再依赖运行时 UUID。草稿实现自定义解码，为版本 1 缺少新字段的数据提供默认值，确保已有请求无损打开。`HTTPResponseSnapshot` 提供与持久化响应之间的显式转换，网络层仍不直接操作数据库。

## 光标与验证

共享设计系统增加 macOS 13 可用的 pointing-hand 修饰器。它只用于 Button、Menu 触发器、标签页、树/列表选择行和其他明确点击目标；输入框、文本编辑器与普通容器不应用。测试覆盖旧草稿兼容、响应往返保存、POST Header 自动添加与去重、JSON 默认格式化。最后运行项目全量测试、Debug/Release 构建、重新生成应用包并检查真实窗口。
