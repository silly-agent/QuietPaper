# 写作聚焦雾化设计

## 目标

普通 Markdown 笔记的标题或正文获得键盘焦点时，将项目栏与文件栏作为一个导航区域柔和雾化，降低写作时的外围干扰。鼠标进入任一左侧栏时，两栏立即恢复清晰；鼠标移出后，如果编辑焦点仍在右侧，则重新雾化。

## 交互边界

- 触发焦点：普通笔记的标题输入框、Markdown 正文编辑器。
- 不触发焦点：搜索框、格式工具栏、阅读预览、HTTP 请求文件、数据库连接文件。
- 解雾范围：鼠标进入项目栏或文件栏时，两栏作为整体恢复清晰，避免一栏清晰、一栏模糊造成割裂。
- 编辑器顶部：正文独占焦点时，面包屑、标题、模式按钮和格式工具栏一起雾化；鼠标进入顶部区域时恢复清晰。标题正在输入时顶部始终清晰，避免影响编辑。
- 可用性：雾化只改变视觉效果，不关闭命中测试；用户可以直接把鼠标移入并点击左侧内容。
- 专注模式：左侧栏本来就不可见，因此不应用额外效果。
- 用户设置：外观设置提供持久化开关，默认开启；关闭后左侧导航始终保持清晰。

## 视觉方案

使用 SwiftUI 原生 `blur` 产生小半径高斯模糊，同时轻微降低饱和度与不透明度。进入与退出采用约 0.18 秒的缓动；系统开启“减少动态效果”时取消动画。该效果不添加遮罩层，避免拦截 hover、右键菜单和点击。

## 状态与结构

`RootView` 保存一个轻量的 `WritingFocusBlurState`，分别记录右侧编辑焦点、左侧两栏 hover 与编辑器顶部 hover 状态。`NoteEditorView` 上报标题和顶部 hover，`MarkdownEditor` 通过 `NSTextViewDelegate` 上报正文开始/结束编辑。外观设置与根视图通过同一个 `@AppStorage` 键即时同步开关。纯状态对象独立测试所有组合，视图只负责绑定状态和渲染。

## 验收

- 标题或正文聚焦后，项目栏和文件栏同时雾化。
- 鼠标进入任一左栏，两栏同时清晰，且点击与右键正常。
- 鼠标移出左栏且编辑器仍聚焦时，两栏重新雾化。
- 切换到预览、请求文件、连接文件或焦点离开编辑器时不会保留雾化。
- 在设置中关闭功能后，标题和正文聚焦都不会雾化；重新开启后立即恢复。
- 正文聚焦时顶部编辑栏雾化，hover 后清晰；标题输入时顶部不雾化。
- 所有检查使用内存数据库，不访问或修改正式数据库。
