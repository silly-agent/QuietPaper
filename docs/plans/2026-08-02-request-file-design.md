# Quiet Paper 请求文件设计

## 产品范围

Quiet Paper 增加一种与普通笔记并列的文件类型“请求”。请求可以创建在项目根目录或任意模块中，并复用现有的选择、重命名、移动、软删除、恢复、搜索与备份流程。首版支持 HTTP Method、URL、Query 参数、Headers，以及无正文、JSON、纯文本三种 Body；不包含表单、文件上传、认证方案、环境变量、Cookie 管理或请求历史。

请求编辑器采用克制、紧凑的 macOS 工具台风格。顶部是 Method、URL 和主操作“发送”；中部通过参数图标、Headers、Body 切换配置，参数和 Header 均使用可启停、可增删的键值行；底部响应面板直接以 Body 与 Headers 切换，不再重复显示区块标题。JSON 响应自动格式化，文本保持原样并从内容区左侧开始展示，响应内容可以一键复制。请求使用橙色闪电图标，与普通 Markdown 文件形成稳定的视觉区分。

## 数据与架构

在现有 `notes` 表增加非空 `kind` 字段，默认值为 `markdown`，从而无损迁移已有数据。领域模型增加 `DocumentKind`；请求配置使用 `HTTPRequestDraft`、`HTTPKeyValue` 和 `HTTPBodyMode` 等 `Codable` 类型，并以版本化 JSON 保存到现有 `content_markdown` 字段。这样无需建立第二套树节点、删除与备份逻辑，同时为将来的数据升级保留版本入口。

`AppModel` 继续管理标题与内容自动保存，并提供创建项目请求、创建模块请求的方法。选择请求文件时，根编辑区切换为 `HTTPRequestEditorView`；编辑器把结构化草稿编码回内容字段，沿用 600ms 合并保存。全文索引使用请求的 Method、URL、启用的参数、Headers 与 Body 生成可搜索纯文本，不把响应内容写入数据库。

请求由独立的 `HTTPRequestClient` actor 使用系统 `URLSession` 执行。它只接受 `http` 与 `https` URL，合并启用的 Query 参数，应用启用的 Header，在需要时编码请求正文，并返回状态码、响应 Headers、耗时、字节数和可展示文本。网络请求是用户主动操作，不影响笔记、搜索、备份等本地优先能力。

## 状态与失败处理

发送前校验 URL；URL 缺少协议、格式错误或协议不受支持时，在发送栏附近显示明确错误。发送期间按钮变为进度与“取消”，重复发送会取消上一次任务。HTTP 4xx/5xx 仍作为有效响应展示并以不同状态色标识；连接失败、超时和取消分别给出可理解的信息。非 UTF-8 数据使用 UTF-8 容错解码，空响应显示空状态。

请求配置自动保存，响应只存在当前编辑器会话中，切换文件后不写入数据库，也不进入搜索和备份。Header 名称为空的行不会发送；Query 键为空的行不会拼接。Body 为 JSON 时，若内容不是有效 JSON，则阻止发送并定位为正文错误，避免悄悄发送无效载荷。JSON 模式自动补充 `Content-Type: application/json`，但用户显式填写时以用户值为准。

## 验证

数据库检查覆盖旧表迁移默认类型、请求类型持久化、普通笔记兼容以及请求搜索文本。模型检查覆盖项目根目录和模块内请求创建、自动选择及普通笔记/请求编辑器分流。请求构建测试覆盖 Query 编码、禁用行过滤、Header 合并、JSON 校验和正文编码；响应格式化测试覆盖 JSON、纯文本与空响应。最后执行 `./scripts/run-tests.sh`、`swift build`，并启动应用检查浅色/深色布局、键盘焦点、发送/取消状态和窄窗口适配。
