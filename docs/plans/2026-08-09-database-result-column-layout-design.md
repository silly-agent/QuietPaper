# 数据库窄结果表布局设计

## 问题

数据库结果卡的可视区域最小宽度为 380pt，列宽则按内容计算。只有一列或少量短列时，表格实际宽度远小于卡片，SwiftUI 会把这段窄内容放在滚动区域中央，形成两侧大面积留白。单行聚合查询最容易出现这种观感。

## 方案

保留现有表格、导出、滚动和行高结构，只调整显示列宽：

- 内容列总宽度小于结果卡可视宽度时，把剩余宽度平均分配给所有列。
- 单列结果因此自然铺满卡片，标题和值继续左对齐。
- 多个短列均匀利用卡片宽度，不在中间缩成一团。
- 内容本身已经较宽时保持原列宽，继续使用横向滚动。
- 单列仍受现有最大列宽限制之外的“填充宽度”影响，但只用于布局，不改变内容测量与导出数据。

## 边界与验证

不按行数切换展示形式，不新增特殊键值卡，也不改变查询、数据库持久化或导出逻辑。用纯布局计算覆盖单列、多个短列和宽表三种情况，并运行现有内存数据库测试。最后在 `--in-memory-preview` 或脱敏测试数据下检查单列结果是否从卡片左侧铺满显示。
